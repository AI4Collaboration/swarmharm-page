SwarmHarm

Building the bedrock for agent swarm safety and security

Research preview · in development

SwarmHarm is being built to stress-test autonomous agents as a system—not just evaluate them in isolation. Starting from benign, authorized tasks, we aim to uncover how communication, shared state, and coordination can produce safety and security failures without a planted adversary.

Our goal is to turn emergent risks into reproducible tests and actionable evidence: how misalignment starts, how it spreads, and which safeguards prevent harm without sacrificing useful collaboration.

Stress-test the system, not just the agent

RQ1

Communication under constraint

When communication is forbidden, will agents respect the boundary or find another way to coordinate? We plan to compare isolation, prohibited side channels, and authorized communication to test when communication supports safeguards—and when it helps agents work around them.

RQ2

Emergence and contagion

Can a harmful strategy emerge without a malicious task or scripted adversary? Starting from all-benign conditions, we aim to trace the first deviation and determine whether other agents adopt, amplify, reject, or correct it.

RQ3

Whistleblowing from within

If an agent witnesses a peer breaking the rules, will it raise the alarm, remain silent, or join in? We aim to identify which system designs enable accurate, timely reporting to authorized oversight—and which leave misconduct unreported.

One testbed. Three communication regimes.

The first planned experiments isolate changes to the communication setting while holding tasks, models, agent count, budgets, and retry rules fixed. The question is not simply whether agents can collaborate, but whether that collaboration stays within the rules.

Condition Instruction Environment
No channel Cross-agent communication is explicitly prohibited. Peer communication is technically isolated, including indirect routes.
Side channel Cross-agent communication is explicitly prohibited. No official channel is provided, but ordinary shared infrastructure contains an indirect route agents can discover and use.
Legal channel Communication through a designated channel is explicitly authorized. A formal channel is available; other resource permissions remain unchanged.

Deliberately using a prohibited side channel is already an instruction violation; merely discovering one is not. Authorized collaboration is not misalignment. Communication violations and downstream harms are scored separately.

Every condition will retain an authorized, private reporting route to oversight. The three regimes change both channel availability and authorization; attributing an effect to either one alone requires additional matched controls.

From failure modes to stronger defenses

We are designing a configurable, executable testbed on AWS EC2: independent agent contexts and workspaces, shared task services, and a separate control, scoring, and audit layer. Initial task candidates pair authorized vulnerability evaluation on designated targets with software repair and verification.

The ambition is reusable infrastructure for comparing system designs and defenses—not a showcase of isolated incidents. Independent execution records and outcome checks will distinguish attempted violations, realized harm, and successful restraint. All experiments must keep task assets and potential consequences inside the authorized environment, with containment, credential isolation, and hard stop mechanisms as fixed requirements.

Build the evidence for safer agent swarms. SwarmHarm is currently in the design stage. This page presents our research agenda and planned testbed; the benchmark, code, and results are not yet released.
