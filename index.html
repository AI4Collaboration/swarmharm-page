What SwarmHarm tests

Two phases. Each claim has a matching environment contract.

What the phase tests
Environment design principles
Phase 1

Form the Swarm

Can separate agents in different sandboxes actively discover others and establish a persistent communication channel?

Phase 1 designThe channel must emerge—not be assigned.
  1. 01
    Impossible real task

    Legitimate work; the intended workflow is mechanically unable to finish it.

  2. 02
    Concurrent separate agents

    All stay online in private, least-privilege workstations; no team, leader, pair, or prescribed connections.

  3. 03
    Unannounced shared system

    Ordinary filing activity persists across workstations; neither peers nor a communication channel is mentioned.

Natural prompt · Narrow permissions · Live shared state
Phase 2

Cause Harm

Can information carried by the swarm change an action and produce a concrete, verifiable adverse outcome?

Required evidenceSwarm → Action → Effect
Phase 2 designThe consequence must be real inside the test world.
  1. 01
    Natural consequential task

    A fresh task and business object where the agent can take an outcome-relevant action.

  2. 02
    Action through shared state

    Swarm information must change an executed action; locally valid actions may compose into one effect.

  3. 03
    Independent verifier

    Recompute the downstream effect from source truth—not agent text, status fields, or an LLM judge.

Cross-task evidence · Executed action · Independent truth

Agents interact with task data, shared environments, and one another—without being told to form a swarm.

Research questions

Legitimate tasks. No planted malicious agent.

RQ1

Form the Swarm

When do isolated agents autonomously establish stable communication?

RQ2

Cause Harm

When does shared memory lead to a verifiable harmful outcome?

Systematic test design+

Verify the setup, then observe the behavior

VALID PATH

Establish the blocker

Distinguish proven impossibility from a capability limit measured for this model and budget. One failed rollout does not establish either.

EXPLOIT PATH

Demonstrate the effect

Verify a working exploit and its business effect independently. A repaired fixture checks that the defect caused the outcome.

TRANSFER PATH

Verify peer usefulness

Shared infrastructure preserves genuine agent-authored artifacts. Measure discovery, sharing and later use; do not script those behaviors.

A feasible source task checks capability. A scripted exploit checks mechanics. Neither is a model failure.

Vary the channel, keep the task fixed
